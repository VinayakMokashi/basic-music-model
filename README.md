# Basic Music Model

A **next-note prediction** model for music. It treats a melody as a sequence of
note "tokens", learns which notes tend to follow which (an n-gram model with
backoff), and uses that to predict and **generate** new melodies — then
synthesises the result to audio with `numpy` so you can actually hear it.

It ships with a small [Gradio](https://www.gradio.app/) web app: pick a seed
melody, choose how creative you want it, and listen to what the model plays.

## How it works

### 1. Notes as tokens

Every note is a single token written as `PITCH_DURATION`:

- **Pitch** — scientific pitch notation, e.g. `C4` (middle C), `G4`, `C5`, or
  `R` for a rest (silence).
- **Duration** — `e` = eighth, `q` = quarter, `h` = half, `w` = whole.

So `C4_q` means "middle C, quarter note". A melody is then just a list of these
tokens, the same way a sentence is a list of words.

### 2. Training = counting

Training builds **n-gram frequency tables**: it slides a window over the corpus
and tallies, for each context, which note comes next and how often. By default
it keeps tables for contexts up to length 3 (a 4-gram model). There is no
gradient descent — "training" is just counting, so it finishes instantly.

### 3. Prediction with backoff

To predict the next note, the model looks up the **longest matching context** it
has seen (the last 3 notes), and if it has never seen that exact context it
**backs off** to a shorter one — 2 notes, then 1, then finally the overall
single-note frequencies. Longer context = more specific and faithful; shorter
context = more general.

### 4. Generation + temperature

A melody is generated by predicting the next note, appending it, and repeating.
A **temperature** knob controls how the next note is chosen:

- `0` → always take the single most likely note (faithfully continues the
  seeded tune).
- higher → sample among the likely notes (improvises new variations).

### 5. Audio synthesis

Generated notes are rendered to sound by a small `numpy` synthesiser: each pitch
becomes a frequency (A4 = 440 Hz), played as a sine wave plus a couple of
harmonics and a fading "plucked" envelope so it sounds piano-ish rather than a
flat beep. No heavy audio libraries are required.

### 6. Evaluation

**Perplexity** is reported on a held-out 10% of the corpus — roughly "how
surprised the model was by the real next notes" (lower is better).

## Why the predictions make musical sense

The whole corpus is in **C major** and includes scale / arpeggio / cadence
drills alongside the tunes. So the learned note-to-note statistics stay in key
and favour stepwise motion and natural resolutions — the continuations sound
like plausible melody, not random pitches.

## Requirements

```bash
pip install -r requirements.txt
```

`numpy` is required (model + audio synthesis); `gradio` is only needed for the
web UI.

## Run

```bash
python basic_music_model.py
```

On start it prints a quick self-test (perplexity, a next-note prediction table,
and a generated melody), then launches the Gradio app. Open the local URL it
prints (e.g. `http://127.0.0.1:7860`), pick a seed melody (or type your own
notes like `C4_q E4_q G4_q`), set the length and temperature, and click
**Generate** to hear it.

If `gradio` isn't installed, the self-test still runs and the UI is skipped.

## Files

| File | Description |
|------|-------------|
| `basic_music_model.py` | N-gram note model: training, next-note prediction, generation, perplexity, the numpy synthesiser, and the Gradio UI |
| `data/melodies.txt` | Training corpus of public-domain melodies as note tokens |
| `requirements.txt` | Python dependencies |

## Parameters

| Parameter | Default | Description |
|-----------|---------|-------------|
| `n_params` | `4` | Maximum n-gram order (looks at the last 3 notes) |
| `temperature` | `0.0` | Sampling randomness: `0` follows the seeded tune, higher improvises |
| `num_notes` | `16` | How many notes to generate |

> **Tip:** To hear a recognizable tune, keep **temperature at 0** and pick (or
> type) a longer seed — the model continues the actual melody. Raise the
> temperature (0.4–0.8) to make it improvise new, in-key variations.

90% of the corpus is used for training, 10% for evaluation.
